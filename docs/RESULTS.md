## Разложение эффектов

Провал cover относительно v4 — не одна ошибка, а две независимые, почти равные:

| Изменение относительно v4 | Δ лидерборд |
|---|---|
| **Фикс коллизии синонимов (`syn`), веса не трогали** | **+0.00041** |
| Пер-категорийный препроцессинг (`clean_fixed`) | **−0.00166** |
| + данные cover 1.5M (`cover`) | **−0.00136** |
| + масштаб 3M вместо 1.5M (`cover3m`) | −0.00011 |
| + лишние эпохи human (`v6_fixed` от `clean_fixed`) | −0.00229 |
| LoRA-адаптеры (на старом препроцессинге) | +0.00017 |

Складываются аддитивно: −0.00166 + −0.00136 = −0.00302, измерено −0.00302.

`clean_fixed` — точный контроль: рецепт v4, те же данные, та же опорная точка,
отличается **только** сборкой текста. Он и разделил эффекты.

**Данные cover плохи сами по себе**, при фиксированном препроцессинге, а не
«хороши, но испорчены форматом». Прокси при этом показывал +0.0202.
Направление закрыто: оставшиеся 4.8M уверенных пар трогать незачем.

Удвоение 1.5M → 3M: `llm_holdout` +0.0076, лидерборд −0.00011. Плоско.

## Обе локальные метрики указывают в неверную сторону

**`llm_holdout`.** Ранговая корреляция с лидербордом по четырём точкам с известным
LB и известным прокси (v4, lora, cover, cover3m): **ρ = −0.8**. Не «слабо
предсказывает» — систематически предсказывает наоборот. Опровергнут трижды:
адаптерами (+0.0084 → LB +0.0002), cover (+0.0202 → LB −0.0030),
cover3m (+0.0076 → LB −0.0001).

**`human_val`.** `v6_fixed` — чемпион по `human_val` (0.7887, лучший результат за
сессию) и худший из успешных сабмитов на лидерборде (0.51745).

**Калибровка отозвана.** Коэффициент переноса 0.82 был подогнан по двум точкам
(v3→v4) и опровергнут третьей: 0.0278 × 0.82 предсказывало +0.023, получено −0.003.
Экстраполяции вида «LB 0.55 требует прокси 0.779» недействительны.

Увеличивать точность прокси бессмысленно: ошибка не в дисперсии, а в валидности.

## Фикс коллизии синонимов — что именно сделано

У 16.8% товаров каталога канонический ключ собирается из двух разных исходных
полей, у 9.9% значения при этом **различаются**, и раньше побеждало то, что
стояло раньше в JSON. Порядок источников измерен напрямую — на положительных
парах считалась доля случаев, когда значение из источника совпало со значением
партнёра:

| Группа | Источник | Совпал с партнёром |
|---|---|---|
| артикул | `партномер (артикул производителя)` | **58.2%** |
| | `артикул` (маркетплейсовый) | **0.9%** |
| цвет | `цвет товара` | 30.3% |
| | `название цвета` | 13.9% |
| размер | `размер производителя` | 6.3% |

Обычный lift для выбора источника не годится: стороны пары приходят из **разных
схем атрибутов**, и пар, где один и тот же исходный ключ есть у обоих, почти нет
(`страна-изготовитель` есть у 40% товаров, а пар с ним у обоих — 2).

Эффект до обучения: совпадение `артикул` на положительных парах 13.4% → 29.4%.
Текст меняется у 0.85% товаров полного каталога, регрессия нулевая.

**Обе локальные метрики этот прирост не увидели** (`human_val` −0.0006,
`llm_holdout` +0.0004) — очередное подтверждение, что решения по ним принимать нельзя.
Подробности замера — в `ATTRIBUTES.md`.

## Дообучение под фикс (`ce_syn`) — отрицательный результат

21 августа, L40S: старт с финальных весов v4, одна replay-стадия
(human 292k + LLM 292k 1:1), lr 5e-6 вместо 1e-5, свежий seed LLM-выборки.
9131 шаг, 2.9 часа.

| Шаг | `human_val` | `llm_holdout` |
|---|---|---|
| 0 (веса v4 + исправленный препроцессинг) | 0.7755 | 0.7444 |
| 4565 (`half`) | 0.7810 | 0.7435 |
| 9131 (`final`) | **0.7832** | 0.7445 |

`human_val` +0.0077, `llm_holdout` неподвижен. Это подпись переобучения на
второй эпохе по human, а не улучшения: та же картина была у `v6_fixed`
(`human_val` 0.7887 — рекорд сессии, лидерборд 0.51745 — худший из успешных).
Снижение lr вдвое уменьшило эффект примерно вдвое (+0.0071 к v4 против +0.0126
у `v6_fixed`), но не устранило.

**Вывод: выравнивать веса под исправленный препроцессинг не нужно.** Сам фикс
даёт +0.00041 при нулевых затратах, а попытка дообучить под него отнимает
больше, чем добавляет. Чекпоинты лежат в `s3://mm-ml-matching-env-dev/smm-iparfenov/xak/ce_syn/`,
на лидерборд не отправлялись.

Побочно выяснено: скрипты из `ce_bundle.zip` требуют новый transformers.
На 4.44.2 у XLM-R нет SDPA, обучение с batch 64 x 384 не влезает в 46 ГБ
(нужен gradient checkpointing, он же роняет скорость до 0.98 it/s), и kwarg
загрузки называется `torch_dtype`, а не `dtype`.

## Что сработало

Всё, что дало плюс, было получено до 18 августа и подтверждено лидербордом:

**Cross-encoder вместо эмбеддингов.** Косинус `USER-bge-m3` — 0.3742 на `human_val`,
дообученный cross-encoder — 0.7750. Негативы предотобраны как hard negatives,
нужен cross-attention.

**LLM-данные смешанной уверенности до 1.5M.** v1 → v3 → v4: LB 0.4454 → 0.5074 → 0.5214.
Главный и единственный рычаг, который реально доехал до лидерборда.

**Replay вместо последовательных стадий.** Чистое дообучение на human роняло
генерализацию 0.7309 → 0.6683. Подмешивание LLM 1:1 сохранило её.

**Детерминированный выбор источника при коллизии синонимов.** +0.00041 на
лидерборде, ноль GPU-часов. Единственная правка сессии, механизм которой
не зависит от человеческого среза: это починка недетерминизма, а не подгонка списка.

## Качество разметки

В человеческой разметке ~12% пар в Одежде/Обуви противоречат правилу «разный размер →
разные товары»; у LLM таких 2–5%. Встречаются пары «блузка ↔ футболка» с меткой
«один товар». Для этих категорий это неустранимый потолок.
